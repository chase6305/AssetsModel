# 静态外观网格批处理

本轮已分两阶段合并兼容的静态绘制批次，共 **20 个外观 GLB，主场景绘制批次 265 → 53（−80%）**。两次采用步骤分别减少 120,480 与 58,036 字节；期间另有法线整理，因此这些阶段的文件总大小不能拼成同一个前后基线。以下先说明六个 KUKA KR210 L150 文件的首轮试验，再列第二轮采用记录。

首轮 `Link1` 至 `Link6` 的主场景三角形绘制批次从 **153 降至 8（−94.8%）**，总体积从 **6,711,808 降至 6,591,328 字节（−1.8%）**。对应[试验记录](quality/batching-trial.json)与[独立核验](quality/batching-independent-validation.json)。

该处理保留原表面、角点法线和材质。它不会减少三角形数、改变机器人运动学、删除 CAD 的正反面副本，或把不同颜色的零件合成同一个材质。主场景与辅助线场景分别核对，辅助线保持原有可见范围。

| 外观网格 | 主场景批次（原 → 试验） | 文件字节（原 → 试验） |
| --- | ---: | ---: |
| Link1 | 67 → 2 | 881,508 → 825,528 |
| Link2 | 6 → 1 | 2,491,068 → 2,491,344 |
| Link3 | 24 → 2 | 894,780 → 875,620 |
| Link4 | 4 → 1 | 509,180 → 506,184 |
| Link5 | 2 → 1 | 1,070,996 → 1,069,996 |
| Link6 | 50 → 1 | 864,276 → 822,656 |

Link2 增加了 276 字节；这轮主要收益是减少绘制批次。试验中，trimesh 的 Link1 加载中位数从约 9.22 ms 降至 1.22 ms，Link6 从 4.70 ms 降至 0.51 ms。每项仅运行 5 次，结果反映当次机器与加载器，不能视为所有应用的性能保证。

## 验证范围

写入试验树之前，脚本对每个场景比较三角形与线段的有向角点多重集合，包括每个角点的全部属性原字节、材质索引、节点变换和计算后的世界位置/法线；材质数组必须完全相同。顶点只在全部属性字节一致时合并，因此同位置的硬边、反向法线、UV 与颜色边界保留。去除未引用顶点不会改变可见表面。

独立核验使用另一套基于标准库 `struct` 的解码和逐角点计数，没有调用批处理脚本的比较函数；六份输入/试验文件的 SHA-256 与试验记录相符。当前六份源文件的节点均为平铺、单位变换；主场景与第二场景的有向表面集合均完全相等。包含这六份试验文件的 14 个 GLB 通过 Khronos 官方校验，0 错误、0 警告。回归测试覆盖硬边、不同材质、辅助场景、变换、32 位索引、字节颜色对齐和显式拒绝的输入。

Link1 和 Link3 分别有 2,032 与 628 组跨材质重合表面。独立检查确认它们全是反向绕序的单面材质，属于 CAD 显式正反面；合并后仍保留两面的不同材质。脚本拒绝同向异材质重合面，以及任一侧启用双面渲染的异材质重合面，避免改变依赖绘制顺序的覆盖关系。

## 复现试验

需要仓库的可选网格依赖。输出必须在资产树之外；脚本只读源文件，不覆盖默认模型，也不覆盖内容不同的既有试验输出：

```bash
python3 scripts/batch_visual_meshes.py \
  --files RobotModel/KUKA/KR210_L150/Visual/glb/Link1.glb \
          RobotModel/KUKA/KR210_L150/Visual/glb/Link2.glb \
          RobotModel/KUKA/KR210_L150/Visual/glb/Link3.glb \
          RobotModel/KUKA/KR210_L150/Visual/glb/Link4.glb \
          RobotModel/KUKA/KR210_L150/Visual/glb/Link5.glb \
          RobotModel/KUKA/KR210_L150/Visual/glb/Link6.glb \
  --output /tmp/assetsmodel-batching-trial-new \
  --report /tmp/assetsmodel-batching-trial-new.json
python3 -m unittest discover -s tests -p test_batching.py -v
NODE_PATH=/tmp/assetsmodel-gltf-validation/node_modules \
  node scripts/validate_glb.cjs --root /tmp/assetsmodel-batching-trial-new \
  --json /tmp/assetsmodel-batching-format-new.json
```

官方校验器的安装命令见[网格工作流程](MESH_WORKFLOW.md)。采用试验时，还需要使用相同姿态、相机和灯光比较正面、背面与顶部，并再次运行 URDF 三姿态装配比较。批处理输出只包含指定 GLB；需要渲染完整 URDF 时，把它们放进模型目录的副本中，其余资源沿用原目录。

当前实现只处理平铺的静态索引三角形/线段。纹理、透明材质、蒙皮、动画、扩展、层级节点、稀疏访问器，以及会丢失的 mesh/accessor/bufferView 元数据均明确拒绝。不同节点变换、场景成员范围或属性类型不会混在一起。内部 GLB mesh/node 名称会改为 `batch-*`；URDF 链接名、关节名、坐标和材质名称不变。

原有 389 个外观 GLB 的初始结构调查发现 27 份主场景至少有 5 个绘制批次；该清单只用于寻找候选，不作为自动采用依据。

## 本轮采用

六个 KR210_L150 外观 GLB 已采用试验结果，详见 [写入记录](quality/batching-applied.json)。这六份文件默认场景的三角形绘制组由 153 降为 8，总文件减少 120,480 字节。全部三角角点、法线、材质和辅助线场景保持相同。

[EEVEE 三视角对比](quality/batching-eevee-comparison.json)中，正面斜视与顶视逐像素一致；背面斜视只有 3 个像素相差 1/255。[对比图](previews/kuka-batching-eevee-review.jpg)使用原生单面剔除。Cycles 会忽略单面剔除，原 CAD 正反异色共面表面会随 BVH/面次序出现黑斑差异，不能用来替代该项验收。

上述降幅对应记录中 `source_sha256` 的采用前文件。当前资源已经批处理；直接以当前资源重跑会验证当前结果，不应再得到同样的 153→8 降幅。要复现该降幅，请在 `--root` 指定的独立输入树中使用采用前文件。

第二轮已采用另外 **14 个 GLB / 8 款机器人**，主场景批次 **112 → 45**，总大小 **6,825,692 → 6,767,656 字节**，全部文件均缩小。详见[第二轮写入记录](quality/batching-round2-applied.json)。其中 10 个输入在法线优化后已改变，全部 14 份试验均从最新输入重新生成；没有使用会覆盖新法线的旧试验文件。

这 14 份文件逐场景的有向位置、法线、材质与辅助线多重集合严格相等，Khronos 校验为 0 错误、0 警告。8 款机器人以相同设置比较前后正背两视角，共 16 对：13 对逐像素一致，其余最大差值 1–2/255，像素一致率至少 99.9955%。该结果只说明本次批处理保持外观，不代表其它网格或渲染器的通用保证。
